# VLESS Aggregator для Happ

Небольшой агрегатор публичных VLESS-подписок. Он параллельно скачивает источники, понимает обычные и base64-подписки, оставляет только VLESS с `security=tls` или `security=reality`, удаляет дубликаты по параметрам подключения и проверяет DNS/TCP-доступность узлов.

## Текущий этап

Workflow проверяет до 2 000 TCP-доступных узлов через sing-box: для каждого он запрашивает exit IP у Cloudflare и отдельно проверяет доступ к Google через локальный SOCKS. Источники с собственной проверкой и узлами для РФ проверяются первыми. `all-working.txt` при запуске с `--real-check` содержит подтверждённые VLESS, а `tcp-open.txt` — результат дешёвой проверки.

После определения страны workflow замеряет скорость всех подтверждённых узлов, если их не больше 60. Для большего числа берётся до 20 самых быстрых по задержке узлов из каждой страны, но не более 60 за запуск. Каждый замер скачивает 2 МБ через проверяемый VLESS. В `best.txt` и country-файлы попадают только узлы, прошедшие и HTTP-проверку, и speed-test; до 10 разных exit IP на страну. В их названиях указаны страна, измеренная скорость и задержка HTTP-запроса. Рейтинг учитывает скорость (45%), задержку (30%), работу в последних пяти запусках (20%) и тип защиты (5%).

Чтобы получить country-файлы, добавьте в GitHub Secrets секрет `IPINFO_TOKEN` от [IPinfo Lite](https://ipinfo.io/developers/lite-api). Workflow определяет страну по exit IP. Уже определённые IP сохраняются в `output/ip-country-cache.json` на 30 дней: в следующих запусках в API отправляются только новые или устаревшие IP. Без токена страны будут `ZZ`, но реальная VLESS-проверка продолжит работать.

## Запуск локально

```powershell
python src/main.py
```

Для проверки только парсинга и дедупликации без сетевых TCP-проверок:

```powershell
python src/main.py --skip-check
```

Обычная TCP-проверка теперь использует таймаут 2 секунды и 128 параллельных workers, а во время работы печатает прогресс. Параметры можно изменить: `--check-timeout 1.5 --check-workers 200`.

Для реальной проверки нужен установленный `sing-box` и `curl`:

```powershell
python src/main.py --real-check --sing-box-bin C:\path\to\sing-box.exe
```

Для определения стран при локальном запуске задайте `IPINFO_TOKEN` в переменной окружения PowerShell перед этой командой: `$env:IPINFO_TOKEN = "ваш-токен"`.

По умолчанию `security=none` отбрасывается. Для диагностического запуска его можно оставить так:

```powershell
python src/main.py --include-insecure --skip-check
```

Результаты:

- `output/best.txt` — до 10 проверенных узлов на страну с измерениями в названии; без `--real-check` файл будет пустым;
- `output/all-working.txt` — подтверждённые VLESS при `--real-check`, иначе TCP-доступные узлы;
- `output/tcp-open.txt` — TCP-доступные узлы во время `--real-check`;
- `output/countries/ZZ.txt` — узлы без определённой страны;
- `output/ip-country-cache.json` — кеш стран по exit IP;
- `output/stats.json` — статистика запуска;
- `history.json` — простая история присутствия узлов по дедупликационному ключу.

Число лучших узлов меняется константой `TOP_N` в `src/main.py`.

## GitHub Actions

Workflow `.github/workflows/update.yml` запускается вручную или каждые два часа в 17 минут (`17 */2 * * *`). Он требует, чтобы Actions были разрешены, а workflow находился в default branch. Для автоматического коммита используется `contents: write`. Проверка ограничена 2 000 VLESS и 60 загрузками по 2 МБ за запуск.

Задержка и скорость измеряются из сети GitHub runner, а не с телефона. Даже узел, прошедший проверку на runner, может быть недоступен у вашего провайдера. Чтобы отбирать именно доступные из вашей сети узлы, проверку придётся запускать из этой сети, например на собственном runner.

Источники находятся в `sources.json`. Если конкретный источник временно недоступен, запуск продолжает обработку остальных и записывает ошибку в `output/stats.json`. Источник rjsxrd пока отключён: опубликованный путь `vless-secure.txt` возвращает 404.

Публичные конфигурации могут быть небезопасными или принадлежать неизвестным владельцам. Не передавайте через них чувствительные данные и проверяйте требования законодательства и правила использования сети.
